System Architecture

Two systems.
One platform.

[ 01 ] Real-Time Queue Engine
Server-Pushed Position Updates
Socket.io persistent connections push queue state to every connected patient. No polling. No refresh. Patients track their live position from anywhere — home, parking lot, another floor.
[ 02 ] Remote Join
Eliminate the Physical Waiting Room
Patients join the queue from their phone before arriving. The system estimates wait time, notifies when they're next, and lets them arrive precisely on time — no crowded lobbies.
[ 03 ] Doctor Controls
Call · Skip · Defer from Dashboard
Doctors manage their queue in real time. Every action — call next, skip, defer — triggers an immediate push to all affected patients. The admin panel reflects every state change with an audit timestamp.
[ 01 ] Granular Consent
Per-Doctor, Per-Record Access Control
Patients grant or revoke consent on individual records — not blanket access. A cardiologist sees only what you've authorized. Revoke instantly. Every consent event is timestamped and immutable.
[ 02 ] Encrypted Storage
AES-256-GCM · Field-Level Encryption
Every medical record is encrypted at the field level before storage. MongoDB never sees plaintext. The encryption key lifecycle is patient-controlled, not server-controlled.
[ 03 ] Audit Trail
SHA-256 Integrity · Tamper-Evident Logs
Every access, share, and modification generates a log entry chained with a SHA-256 hash. Any tampering with historical log entries invalidates the chain — detectable immediately by the integrity verifier.

Health Vault

Your records.
Your keys.
Your consent.

Health Vault treats medical data as patient property — not hospital property. Encryption happens client-side before storage. No plaintext ever reaches the database. Doctors see only what you explicitly authorize, for as long as you allow.

Encryption AES-256-GCM — authenticated encryption with associated data. Each record encrypted with a unique IV. Integrity verified on every read.
Consent Model Granular per-doctor, per-record ACL. Consent grants are time-scoped and revocable. Revocation takes effect immediately — mid-session.
Audit Chain Every access logged with SHA-256 hash chaining. Immutable. Any modification to historical entries breaks the integrity chain — detected by verifier.
Emergency Access Doctors can request emergency access to unconsented records. Access is logged, time-limited, and queued for mandatory admin review.

AI Capabilities
⟳
Groq LLaMA 3 · 70B
Ultra-low-latency inference via Groq's LPU architecture. Triage assessments in under 200ms — fast enough for real clinical workflows.
⊘
Advisory-Only Architecture
The AI presents a structured recommendation with confidence score. It cannot take action. Human clinicians retain full authority and can override with a single interaction — this is non-negotiable.
◈
Structured Symptom Parsing
Free-text symptom input is parsed into structured clinical entities before LLM processing. Reduces hallucination surface and grounds the model in factual patient data.
▲
Priority Queue Integration
A high-urgency triage result can flag a patient for priority queue insertion — still requiring doctor confirmation. The system suggests; the clinician decides.
Security Infrastructure

Authentication
without compromise.

01 — Identity
Two-Factor Authentication
OTP (email/SMS) and TOTP-based MFA (compatible with Authenticator apps). MFA required for any sensitive vault operation — consent modification, emergency access, admin actions.
OTP TOTP / HOTP Speakeasy QR Enroll
02 — Tokens
JWT · Zero localStorage
Access tokens are short-lived (15m). Refresh tokens are stored exclusively in HttpOnly, SameSite=Strict cookies — never in localStorage or sessionStorage. XSS cannot steal tokens.
HttpOnly Cookie SameSite=Strict 15m Access TTL 7d Refresh TTL
03 — Audit
Tamper-Evident Logs
Every auth event, consent change, and record access is logged with a SHA-256 hash chained to the previous entry. The integrity daemon verifies the full chain on schedule — detecting any post-hoc modification.
SHA-256 Hash Chain Integrity Daemon Immutable Log
Admin Analytics

Full operational
visibility.

The admin dashboard surfaces live queue metrics, vault access patterns, security events, and user management — all in a single pane. Redis-backed real-time counters ensure sub-second metric refresh. Every data point has a drill-down to the underlying audit entry.

→
Live Queue Metrics
Active queue depth per department, average wait time, served vs. deferred ratio, doctor throughput — updated via Socket.io in real time.
→
Security Event Log
Failed auth attempts, MFA bypass attempts, emergency access events, and consent anomalies — surfaced with severity classification and linked audit hashes.
→
Vault Access Patterns
Which records are being accessed, by whom, how often, and under what consent scope — with timeline visualization and consent lifecycle tracking.
→
User & Role Management
Create, suspend, or re-role users. View MFA enrollment status. Force password resets. All admin actions themselves are audit-logged and tamper-evident.
